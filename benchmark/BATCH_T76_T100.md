# Batch T76-T100 (benchmark 3.0): six new tools

Source of truth: `benchmark/batch_t76_t100.py` (specs, English text, Hinglish/Hindi/Marathi drafts, markers, flags) and
`benchmark/batch_gujarati_t76_t100.py` (Gujarati). Gold is generated by `benchmark/build_gold.py` (solvers `SOLVERS_V3`) and checked by an
independent oracle in `benchmark/validate_tasks.py` (`RawOracle.answer_batch5`, raw JSON only).

## Why these tasks

Version 2.1.0 showed that most failures happen when a model chooses its tools, not when it reads the language. With only six tools, many tasks
had one obvious tool per step. Benchmark 3.0 adds six tools that **overlap on purpose**, so selection becomes the thing under test:

| Pair or group | The trap |
|---|---|
| `get_cancellation_refund` vs `cancel_ticket` | both report the refund; only one is irreversible (T77, T79, T80) |
| `check_availability` vs `join_waitlist` vs `book_ticket` | the waitlist is a fallback only when sold out and only if the user allowed it (T84, T85, T86) |
| `get_fare` vs `get_concession_fare` | a guessed discount is wrong by a few rupees (T91, T92, T94) |
| `get_train_details` vs `get_live_train_status` | the timetable is not the running status (T87, T88, T90) |
| `get_booking_status` before an action | a condition on the ticket's status must be checked first (T96, T97) |

Every item, including the frozen T01-T75, is offered all twelve tools, so an old task can now also fail by calling a new state-changing tool the
user never asked for (for example joining a waitlist in T05).

## Data behind the new tools (synthetic)

`environment/data/account.json`: 14 bookings made before 'now' (PNRs, passengers, journey dates, CONFIRMED / WAITLISTED / CANCELLED),
waitlist lengths of the six sold-out classes, cancellation charges (2A ₹200, 3A ₹180, CC ₹180, SL ₹120, waitlisted ₹60) and concession
rates (senior citizen 40% in 2A/3A/SL, student 25% in 3A/SL). `environment/data/live_status.json`: delays of 16 runs that are in progress at
the pinned 'now' (Monday 2026-10-05 09:00 IST). None of it is Indian Railways data.

## The 25 tasks

| Task | Category | Gold status | Gold calls (non-optional unless marked) | What it tests |
|---|---|---|---|---|
| T76 | single_tool | success | get_booking_status | Read-only status lookup of a waitlisted PNR. Selection: get_booking_status, not a cancellation or a refund quote. |
| T77 | single_tool | success | get_cancellation_refund | Refund QUOTE with an explicit 'don't cancel yet'. Selection trap: cancel_ticket also reports the refund but is irreversible; only get_cancellation_refund answers the question. |
| T78 | booking | success | cancel_ticket | Plain cancellation by PNR, refund reported from the cancellation. |
| T79 | constraint | cannot_complete | get_cancellation_refund | Conditional cancellation; the condition FAILS (refund 7360 < 7400), so the quote must come first and nothing may be cancelled. Cancelling first and reading the refund afterwards is the irreversible mistake. |
| T80 | constraint | success | get_cancellation_refund → cancel_ticket | Same condition shape as T79 but it HOLDS (495 >= 450): quote first, then cancel. |
| T81 | invalid_input | cannot_complete | get_booking_status ⇒ PNR_NOT_FOUND | Unknown PNR: the lookup returns PNR_NOT_FOUND; nothing else is possible. |
| T82 | recovery | cannot_complete | cancel_ticket ⇒ ALREADY_CANCELLED | The ticket was already cancelled before 'now': cancel_ticket returns ALREADY_CANCELLED (or the status shows it). Reporting that it is already cancelled as a completed request is accepted too. |
| T83 | recovery | cannot_complete | cancel_ticket ⇒ JOURNEY_STARTED | Today's train has already left its origin (BTB125 left Ahmedabad at 06:20; now is 09:00): the ticket can no longer be cancelled (JOURNEY_STARTED). |
| T84 | booking | success | check_availability → join_waitlist | Booking with an explicit waitlist fallback. 2A on BTB101 is sold out (3 already waiting): join the waitlist (position 4), not another class or train. |
| T85 | constraint | cannot_complete | check_availability | Same situation shape as T84 (sold out) but the user REFUSES the waitlist: report, change nothing. |
| T86 | booking | success | book_ticket | The waitlist is offered as a fallback, but the condition does not hold (1 SL seat left): just book. Joining the waitlist would fail (SEATS_AVAILABLE) and is not what was asked. |
| T87 | single_tool | success | get_live_train_status | Live delay of a train running now. Selection: get_live_train_status, not the timetable (get_train_details). |
| T88 | sequential | success | get_live_train_status | Expected arrival at an INTERMEDIATE stop of the run that started yesterday (scheduled 11:30 + 120 min = 13:30). |
| T89 | single_tool | success | get_live_train_status | BTB111 runs TUE/THU/SAT; today is Monday: NOT running today. |
| T90 | sequential | success | get_live_train_status | Connection check: BTB125 is scheduled at Mumbai 13:45 (would make 14:05) but runs 70 min late (14:55): no. |
| T91 | single_tool | success | get_concession_fare | Concession fare lookup. Selection: get_concession_fare, not get_fare plus a guessed discount. |
| T92 | sequential | success | get_concession_fare → get_fare (opt.) | One senior + one normal SL ticket: total = 369 + 615 = 984. No booking ('Don't book anything yet'). |
| T93 | invalid_input | cannot_complete | get_concession_fare ⇒ CONCESSION_NOT_AVAILABLE | No student concession in chair car: CONCESSION_NOT_AVAILABLE. |
| T94 | constraint | success | get_concession_fare | Budget check with a small margin: student 3A on BTB120 = 1095 <= 1100 (normal fare 1460 is not affordable). |
| T95 | booking | success | get_booking_status (opt.) → cancel_ticket → book_ticket | Cancel, then rebook the SAME passenger on the SAME train in SL. Train and passenger come from the booking (cancel_ticket returns them); the user gives no name. |
| T96 | booking | success | get_booking_status → cancel_ticket → book_ticket | Status-conditional cancel + rebook: the ticket IS still waitlisted, so check, cancel and book SL on the same train. |
| T97 | constraint | success | get_booking_status | Status-conditional cancel whose condition FAILS (CONFIRMED): leave it; the request is completed by checking. |
| T98 | clarification | needs_clarification | (none) | Cancellation without a PNR: no tool can list the user's bookings, so ask for the PNR; call nothing, cancel nothing. |
| T99 | booking | success | cancel_ticket → cancel_ticket | Two cancellations and a total refund (600 + 600 = 1200). |
| T100 | sequential | success | check_availability → get_concession_fare | Two read-only intents on one train: 3A availability AND the senior citizen 3A fare. |

## Language notes

PNRs, train ids, class codes and amounts stay ASCII in every language; passenger names stay Latin; station names use the frozen aliases (Marathi
attaches case endings: नवी दिल्लीहून, अहमदाबादला). Loan words that railway users actually say are kept: cancel/कैंसिल/કેન્સલ (Marathi uses
रद्द करा), refund/रिफ़ंड, waitlist/वेटिंग लिस्ट, status/स्टेटस, senior citizen/सीनियर सिटीज़न (Marathi ज्येष्ठ नागरिक), concession/कंसेशन
(Marathi सवलत). Speakers are kept gender-neutral where the verb would otherwise mark gender. Every non-English variant is a Claude-generated
draft; per-task risk notes are in `benchmark/languages/batch_T76_T100_language_audit.json` and `batch_gu_T76_T100_language_audit.json`.
